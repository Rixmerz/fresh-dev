# Fixtures

Static-analysis inputs for the `fresh-dev` plugin (`fresh` MCP server,
validators, hooks, detection). **Nothing in here is meant to be run.** Every
TS/TSX file is syntactically valid for the Fresh version it targets, but the
fixtures are read, parsed and asserted on — never executed. The hand-written
sets each carry an `EXPECTED.md` with the facts the test-suite asserts
(detection, route table, layouts/middlewares per route, islands, boundaries,
validator findings, `fresh_trace` URL table).

## Conventions

- Hand-written fixtures use generic domain vocabulary (blog, admin, docs, shop,
  pricing). No real client names.
- Files whose header comment starts with `DEFECT (<rule>)` are the positive
  cases for that validator rule. Do not fix them, and do not regenerate
  `fresh-1.x-layered/fresh.gen.ts` — its two discrepancies are the R008 case.
- `static/favicon.ico` in the hand-written sets is a 0-byte placeholder.
- `deno.lock` is only present in the generated 2.x fixtures.
- Route URL patterns in `EXPECTED.md` are written in the documented
  `pathToPattern` form: `index` dropped, `(group)` dropped, `[x]` → `:x`,
  `[...x]` → `:x*`, `[[x]]` → `{/:x}?`. Fresh 2's crawler also keeps an internal
  variant with groups and a trailing `/` for index files; the documented form is
  what `fresh_routes` reports.
