# fresh-architecture

Fresh has three shapes in the wild, and most structural mistakes come from applying one
shape's rules to another. Detect first, then place code by what it may import, not by
where it feels it belongs.

References: `references/anatomy.md` (files per flavor, verbatim scaffolds),
`references/boundaries.md` (the classification model), `references/migration-1x-2x.md`
(diagnostic checklist), `../_shared/references/versions.md`.

## Before touching anything

| Question | Call |
|---|---|
| Which version and flavor, on what evidence? | `fresh_project(workspace="/abs/path")` — `version`, `flavor`, `freshVersion`, `entry`, `staticDirs`, `evidence`, `confidence`; `apps[]` in a Deno workspace |
| What runs where today? | `fresh_boundaries(workspace="/abs/path", only_violations=false)` — per-module `server`/`client`/`shared`/`unknown` |
| What does a config or entry change touch? | `fresh_impact(workspace="/abs/path", files=["main.ts"])` |
| What does a module pull in, resolved through the import map? | `fresh_dependencies(workspace="/abs/path", file="lib/db.ts", include_external=true)` |
| Is the project structurally sound before I start? | `fresh_validate(workspace="/abs/path", categories=["dependencies", "conventions"])` |

## Decision rules

### Three shapes (Fresh docs: file-routing, advanced/vite, advanced/builder)

| | 1.x manifest | 2.x Vite (default of `jsr:@fresh/init`) | 2.x builder (`--builder`) |
|---|---|---|---|
| entry | `main.ts` `start(manifest, config)`; `dev.ts` `dev(import.meta.url, "./main.ts", config)` | `main.ts` exports `app = new App<State>()`, `app.use(staticFiles())`, `app.fsRoutes()`; **no `listen()`** | `dev.ts` with `Builder` from `fresh/dev`; `main.ts` as in Vite |
| route table | `fresh.gen.ts` (checked in, regenerated by `dev.ts`) | filesystem crawl at dev/build | filesystem crawl |
| config | `fresh.config.ts` `defineConfig({ plugins })` | `vite.config.ts` `plugins: [fresh()]` | `new Builder({ staticDir, islandDir, routeDir, ignore, ... })` |
| client entry | none | `client.ts` importing `assets/styles.css` | none; CSS in `static/` plus `<link>` in `_app.tsx` |
| typed helpers | `defineRoute/Layout/App` from `$fresh/server.ts` | `utils.ts` `createDefine<State>()` | same |
| build | `_fresh/snapshot.json`, `_fresh/static/` | `_fresh/server.js`, `_fresh/server/`, `_fresh/client/` | `_fresh/server.js` |
| run | `deno task start` (watches `dev.ts`) | `deno task dev` (vite); `start` = `deno serve -A _fresh/server.js` | `deno task dev` (`dev.ts`) |

Detection weight: `deno.json` `imports` is decisive (`"fresh"` containing `@fresh/core`
= 2.x, `$fresh/` = 1.x); `fresh.gen.ts` is decisive for 1.x; `vite.config.ts` versus
`dev.ts` with `Builder` picks the 2.x flavor; `routes/` alone proves nothing.

### Where new code goes

| The code | Goes in | Because |
|---|---|---|
| serves a URL | `routes/` (`.ts` API, `.tsx` page) | the crawler reads only `routes/` |
| needs events, hooks, browser APIs | `islands/` or `routes/**/(_islands)/` | only islands hydrate |
| renders markup, no state | `components/` | server by default, may be shared |
| touches `Deno.*`, a DB, env, `node:` | a server-only module (`lib/`, `db/`; name it so) imported by handlers and middleware only | B001 if an island reaches it |
| pure helpers used by both sides | a module with no server or browser signal | it becomes `shared`; B004 if its name claims otherwise |
| referenced by URL (`/logo.svg`) | `static/` (2.x: any configured `staticDir`) | served at the web root |
| imported by code (CSS) in 2.x Vite | `assets/`, imported from `client.ts` | C009 if it sits in `static/` |

### Configuration the analyzer checks

- `compilerOptions.jsxImportSource` is `preact`; `jsx` is `precompile` (2.x, with
  `jsxPrecompileSkipElements`) or `react-jsx` (1.x) — D004.
- Every bare specifier is in `deno.json` `imports` or is `jsr:`/`npm:`/`https:`/`node:`
  — D002; a top-level `importMap` file and `deno.jsonc` are honoured.
- One Fresh: `$fresh/` and `fresh`/`@fresh/core` never coexist — D003. One `preact` and
  one `@preact/signals` — D005.
- `lint.rules.tags` includes `"fresh"` — C007. `exclude: ["**/_fresh/*"]` keeps the
  build out of lint and check.
- 2.x Vite: `nodeModulesDir: "manual"`, `types: ["vite/client"]`; `deno install`
  populates `node_modules/` (git-ignored). 1.x: `nodeModulesDir: true` only with
  Tailwind.
- Tailwind: 1.x C003 (`static/styles.css` directives, `tailwind.config.ts` `content`,
  plugin in `fresh.config.ts`, npm deps); 2.x C004 (`tailwindcss` + `@tailwindcss/vite`
  in `imports`, `tailwindcss()` in `vite.config.ts`, CSS imported from `client.ts`).

### Migration 1.x → 2.x: diagnose only

This plugin does not perform migrations. `references/migration-1x-2x.md` lists what
changes and which rules fire on a half-migrated tree (D003, R012/R013, B003, R008, R017,
R020). The official path is `deno run -A -r jsr:@fresh/update .`; `fresh/compat` exports
1.x-style aliases for the transition. Report the checklist; do not start rewriting
handlers.

### Neighbours

`fresh_graph_export(workspace="/abs/path")` writes `.fresh-dev/graph.json` (Graphify
node-link) for livespec's `ingest_external_graph`: `renders`/`hydrates` as
`uses_component`, `handles`/`passes_data` as `uses`, optionally `wraps`/`guards` and
`imports`. URL patterns, kinds, boundaries and assets stay in `fresh_*`.

## Minimal change

1. Change one config key at a time: `fresh_impact(files=["deno.json"])` before, then
   `fresh_reindex(workspace="/abs/path", force=true)` after.
2. Validate: `fresh_validate(workspace="/abs/path", categories=["dependencies",
   "conventions", "routes"])`, `deno check` (2.x: `main.ts`, `vite.config.ts`; 1.x:
   `main.ts`, `dev.ts`), `deno lint`.

## Traps

| Trap | ID |
|---|---|
| Bare import not in the import map | D002 |
| `$fresh/` mixed with `fresh`/`@fresh/core` | D003 |
| Wrong `jsx` or `jsxImportSource` | D004 |
| Two `preact` or `@preact/signals` versions | D005 |
| Import cycle through `routes/` or `islands/` | D006 |
| 1.x `npm:` in an island without `nodeModulesDir` | D007 |
| 2.x Vite `main.ts` calling `app.listen()` | R017 |
| 2.x without `staticFiles()` | R020 |
| 1.x manifest stale | R008 |
| `lint.rules.tags` without `"fresh"` | C007 |
| 2.x imported CSS inside `static/` | C009 |
| Server-named module with no server signal | B004 |

## Precedence

The project's existing conventions outrank this skill; the user's request and safety
outrank both (`engineering-baseline`). A repo on the builder flavor, on a custom
`staticDir`, or with its own `lib/` layout keeps it; never migrate a toolchain as a side
effect of another change.
