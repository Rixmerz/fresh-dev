# fresh-development — the loop

The `fresh` MCP answers questions about a Fresh project; it never edits it. Every
`fresh_*` tool is a read-only query (only `fresh_graph_export` writes, and only under
`<workspace>/.fresh-dev/`). Claude Code, or a vise agent, makes the change with
Edit/Write; this skill says what to ask before and what to run after.

References: `../_shared/references/tools.md` (all 13 tools, arguments, naming),
`../_shared/references/versions.md` (1.x vs 2.x on one page),
`../_shared/references/rules.md` (validator catalogue).

## `workspace` is required on every call

`workspace` is the absolute path of the Fresh project root: the directory that holds
`deno.json`. There is no cwd or environment fallback (same contract as livespec).

- The SessionStart hook prints it when it detects Fresh; otherwise run `pwd`.
- If `fresh_project` returns `apps[]`, `deno.json` is a Deno workspace: call again with
  the sub-path of the app you are working on.
- Never point it at a folder that holds many repos; the server refuses a path without
  `deno.json`.

## The loop

Run it in order. Each step names the call; skip a step only when an earlier answer
already covered it.

| # | Question | Call |
|---|---|---|
| 0 | Which Fresh, which flavor? | `fresh_project(workspace="/abs/path")` — read `version` and `flavor` before applying any rule below |
| 1 | Which route owns the behaviour? | `fresh_trace(workspace="/abs/path", path="/blog/hello")` for a URL; `fresh_routes(workspace="/abs/path", prefix="/blog")` for a neighbourhood |
| 2 | What does that route render and hydrate? | `fresh_route(workspace="/abs/path", file="routes/blog/[slug].tsx")` — `renders`, `hydrates`, `passes_data`, layouts, middlewares |
| 3 | What does the file I will touch drag in, and who imports it? | `fresh_dependencies(workspace="/abs/path", file="components/PostBody.tsx", direction="importers")` |
| 4 | Which side of the server/client line is it on? | `fresh_boundaries(workspace="/abs/path", only_violations=true)`; the `boundary` field of `fresh_route` and `fresh_components` |
| 5 | Does what I am about to write already exist? | `fresh_components(workspace="/abs/path", name="Post")`, `fresh_islands(workspace="/abs/path", name="Like")`, `fresh_usages(workspace="/abs/path", target="components/PostBody.tsx::PostBody")`; livespec `search_similar` when mounted |
| 6 | Make the minimal change | one file where possible; keep the handler and page shape the file already uses for its version |
| 7 | Validate | `fresh_validate(workspace="/abs/path", files=[...])`, then `deno check`, then `deno lint` |

Before a multi-file change or a brief, add `fresh_impact(workspace="/abs/path",
files=[...])` (or `git={base: "main"}`) and run its `suggestedChecks`.

## Who answers what

| Need | Use | Not |
|---|---|---|
| a symbol's definition, references, implementations, a file outline, an inferred type | the `LSP` tool, backed by `deno lsp` (reads `deno.json`, so `$fresh/`, `@/`, `jsr:`, `npm:` resolve) | grep |
| which file serves a URL, which layouts and middleware wrap it, which islands hydrate, a JSX use of an aliased import, what a middleware scope covers | `fresh_*` | the LSP (no notion of routes, scopes or JSX-by-name) |
| type errors, lint findings | `deno check`, `deno lint` (tag `fresh`) | the `LSP` tool, which exposes navigation, not diagnostics |
| call graph by symbol, dead code, Specs | livespec | `fresh_*` (file and JSX level only) |

`fresh_validate(external={deno_lint: true, deno_check: true})` runs both commands and
merges their findings (`source: "deno lint"`); the default is off because they are slower
than the structural checks.

## Version split, one line each

- 1.x: `handler` export, `(req, ctx)` signature, `ctx.render(data)`, `fresh.gen.ts` is
  the route table (regenerated by `dev.ts`), `$fresh/` imports.
- 2.x: `handlers` (or `handler`) export, `(ctx)` signature, `page(data)` or `{data}`
  return, no manifest (filesystem crawl plus `app.fsRoutes()`), `fresh`/`@fresh/core`
  imports, `createDefine<State>()` in `utils.ts`.

Everything else is in `versions.md`. Never mix the two (D003).

## Minimal change and validation

1. Prefer editing the file the loop pointed at over adding one; prefer a new prop on an
   existing component over a new component (`fresh_usages` first).
2. Keep the handler and page shape the file already uses; the repo's convention wins.
3. Validate in this order and paste the real output in the report:
   - `fresh_validate(workspace="/abs/path", files=["routes/blog/[slug].tsx"])` —
     `ok: true` means no `error`; a file in `summary.unverified[]` was not checked.
   - `deno check` (2.x; the `check` task also runs fmt and lint), or
     `deno check main.ts` (1.x: `main.ts` imports `fresh.gen.ts`, which imports every
     route and island).
   - `deno lint` with the `fresh` tag on (`lint.rules.tags` in `deno.json`, C007) or
     `deno lint --rules-tags=fresh`.

## Traps that cross every skill

| Trap | Caught by |
|---|---|
| 1.x-style `(req, ctx)` handler in a 2.x file; `handlers` export in a 1.x file | R012, R013 |
| `onClick`, `useState`, `useSignal` in `components/` or `routes/`: server-rendered, never hydrated | I004 (`deno lint` `fresh-server-event-handlers`) |
| an island importing, transitively, `Deno.*`, `node:*`, a DB driver, `$std/dotenv` | B001 / I003 |
| 2.x `main.ts` without `app.use(staticFiles())`: island JS is not served | R020 |
| 1.x route added on disk while `fresh.gen.ts` still lists the old set | R008 (`deno task manifest`) |
| `.mts`/`.mjs`/`.cts` under `routes/` or `islands/`, or a `*_test.ts`/`*.test.tsx` name: never crawled | R018, R019 |
| `$fresh/` and `fresh`/`@fresh/core` in one project | D003 |

## Briefing a vise subagent

vise's `frontend` and `backend-typescript` agents preload `engineering-baseline`, their
`*-rules` skill and `ponytail`; they do **not** load plugin skills on their own. The
orchestrator's brief must therefore:

1. Name the skill as the first instruction:
   `Load the fresh-dev:fresh-islands skill before your first edit` (or
   `fresh-dev:fresh-routing`, `fresh-dev:fresh-data-flow`, `fresh-dev:fresh-middleware`,
   `fresh-dev:fresh-components`; `fresh-dev:fresh-development` when the task spans
   several).
2. Give `workspace=/abs/path` verbatim.
3. Paste facts, not prose: the `fresh_route` chain and the `fresh_impact` list as
   `path:line` items, e.g. `routes/blog/[slug].tsx:12 renders components/PostBody.tsx`,
   `islands/LikeButton.tsx:4 prop onSave is a function, not serializable (I002)`.
4. State the validation the agent must run and report verbatim: `fresh_validate`,
   `deno check`, `deno lint`.

A brief that only says "it is a Fresh project" leaves the agent with React habits and
`typescript-rules`; these four lines are what make it a Fresh agent.

## Neighbours

- livespec (`.mcp-docs/docs.db`): symbols and call graph. `fresh_graph_export` writes
  `.fresh-dev/graph.json` for `ingest_external_graph`; `.livespec.toml`
  `[graph] external = ".fresh-dev/graph.json"` with `auto_ingest = true` keeps it fed.
  URL patterns, kinds and boundaries stay in `fresh_*`; livespec does not model them.
- `.fresh-dev/` is this plugin's only footprint (index, dirty marker, graph, warnings);
  add it to `.gitignore` unless the team versions `graph.json`.

## Precedence

The project's existing conventions outrank this skill (rung 3 of `engineering-baseline`,
above any `*-rules` skill and `ponytail`); the user's explicit request and safety outrank
both. When a repo's handler shape, folder layout or naming disagrees with this skill, the
repo wins.
